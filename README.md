# GNSS_COLDSTART_TEST

GNSS 冷启动定位收敛分析工具，支持 **北云 BY（UG016）** 与 **华测 HUACE（M720 / M7 系列）**。工具面向连续录制日志、混合二进制 + ASCII 日志、多次冷启动自动切片，以及室内/室外两种分析口径，输出自包含 HTML、Markdown、PNG 与 JSON。

## 1. 功能概览

- **协议级鲁棒恢复**
  - 不按换行符解析，而是在原始字节流中查找 `#` / `$` 报文锚点；
  - `#` 报文按 32 位 CRC 校验；
  - `$` 报文按 NMEA XOR 校验；
  - 只保留校验通过的完整报文；
  - 二进制块中嵌入的完整 ASCII 报文可以恢复；
  - 随机二进制字节中的 `#` / `$` 不会被误报为报文损坏。
- **动态多次冷启动切割**
  - 不依赖固定时长、固定 GPS 周回落、固定 5×周期或固定采样率；
  - 使用“状态丢失 + 动态间断”识别候选启动边界；
  - 支持不同长短的启动段；
  - 每段按消息偏移切割，消息序列不乱序、不重复。
- **华测定位流动态选择**
  - 在 `BESTPA`、`BESTPOSA`、`RTKPA` 中选择覆盖完整且有效帧数最多的定位流；
  - 分别解析 GMF 与 NovAtel 风格报文头，避免混用时间字段。
- **HMI 自动识别**
  - 不再只看文件名或文件前 2 MB；
  - 对完整文件做协议级恢复后识别北云 / 华测；
  - 混合二进制 + ASCII 日志可正确识别。
- **室内 / 室外两种模式**
  - 室外：各产品独立分析，输出产品报告；
  - 室内：北云与华测按启动序号配对，取共同 t0 后输出联合对比报告。
- **报告与图件**
  - 数据完整性与报文恢复统计；
  - 四个关键时刻；
  - 冷启动耗时分解；
  - 定位类型分段统计；
  - 卫星数量时间轴；
  - 阶段顺序有效性标记。

## 3. 使用方法

### 3.1 HMI

```bash
python gnss_coldstart_hmi.py
```

流程：

1. 下拉选择产品类型；
2. 添加日志文件；
3. 选择场景：
   - 室外冷启动；
   - 室内冷启动；
4. 如文件是一次性连续录制的多次冷启动，勾选：

```text
一次性录制了 N 次冷启动（自动切片）
```

5. 选择输出目录；
6. 点击开始分析。

多产品同时分析时，输出目录下会生成：

```text
beiyun/
huace/
```

单产品分析时，报告直接输出到所选输出目录。

---

### 3.2 命令行

#### 北云

```bash
# 单个独立冷启动文件
python BY_coldstart.py <输出目录> <北云日志>

# 一次性录制的多次冷启动
python BY_coldstart.py <输出目录> --split <北云日志>
```

#### 华测

```bash
# 单个独立冷启动文件
python HUACE_coldstart.py <输出目录> <华测日志>

# 一次性录制的多次冷启动
python HUACE_coldstart.py <输出目录> --split <华测日志>
```

#### 室内联合模式

```bash
python indoor_coldstart.py <输出目录> --split <北云日志> <华测日志>
```

不加 `--split` 时，按单次冷启动包分析。

## 4. 动态切割逻辑

### 4.1 边界证据

切割边界由两类证据共同驱动。

#### 证据一：状态丢失

当前帧满足以下条件时，视为候选启动边界：

- Time Status 尚未完全建立，例如：
  - `UNKNOWN`
  - `APPROXIMATE`
  - `COARSE`
  - `COARSESTEERING`
- Stn ID 为空或 `0`；
- 定位类型处于无解或单点类：
  - `NONE`
  - `SINGLE`
  - `SPPDIFF`
  - `PSRDIFF`

且前一帧处于以下任一状态：

- 差分解；
- 固定解；
- 已有基站 ID。

#### 证据二：动态间断

相邻定位帧时间差满足：

```text
dt > max(2 s, 5 × 实测中位周期)
```

其中实测中位周期由当前定位流动态计算，不预设 1 Hz、5 Hz 或 10 Hz。

---

### 4.2 有效冷启动段条件

一个候选段必须同时满足：

```text
有效帧数 >= 50
段内持续时间 >= 20 s
段首处于启动状态
```

这些是最低质量阈值，不是固定段长，也不限制每段最大时长。

---

### 4.3 时间轴口径

- 自动切割后的 `t=0` 是该段第一条被恢复并通过校验的定位帧时刻；
- 它不是物理断电或物理上电的精确时刻；
- 是否对应真实断电/上电，需要外部开关、事件或视频记录确认；
- 报告中的“有效冷启动段”是基于 GNSS 状态序列与记录间断的推断结果。

## 5. 协议恢复规则

### 5.1 北云

主定位报文：

```text
#BESTGNSSPOSA
```

字段依据：北云《UG016 数据通信接口协议》4.2.2。

### 5.2 华测

候选定位流：

```text
#BESTPA
#BESTPOSA
#RTKPA
```

字段依据：华测《M7系列模组用户指令及协议手册 V2.7》。

#### 华测两种报文头

| 类型 | 报文示例 | GPS 周 | TOW | 单位 |
|---|---|---:|---:|---|
| GMF | `BESTPA` / `RTKPA` | 报头字段 7 | 报头字段 8 | ms，解析时除以 1000 |
| NovAtel 风格 | `BESTPOSA` | 报头字段 6 | 报头字段 7 | s |

两种头部格式分别解析，不做统一假设。

## 6. 指标口径

### 6.1 四个关键时刻

| 指标 | 北云口径 | 华测口径 |
|---|---|---|
| 获得卫星时间 | Time Status 首次脱离 `UNKNOWN` | Time Status 首次脱离 `UNKNOWN` / `APPROXIMATE` |
| 首单点 | 定位类型首次进入单点类 | 定位类型首次进入单点类 |
| 首浮点 | 定位类型首次进入浮点类 | 定位类型首次进入浮点类 |
| 首固定 | 定位类型首次进入固定类 | 定位类型首次进入固定类 |

单点类包括：

```text
SINGLE
SPPDIFF
PSRDIFF
```

浮点类包括：

```text
NARROW_FLOAT
L1_FLOAT
```

固定类包括：

```text
NARROW_INT
WIDE_INT
L1_INT
```

### 6.2 阶段顺序

输出包含：

```text
stage_order_valid
```

用于标记阶段顺序是否满足：

```text
获得时间 -> 单点 -> 浮点 -> 固定
```

如果单点解早于完全有效时标，`时间 -> 单点` 阶段按 0 s 起算，不输出负阶段。

## 7. 输出文件

每次分析输出：

```text
report.html
report.md
summary.json
img_关键时刻.png
img_阶段耗时.png
img_卫星数量时间轴.png
```

`summary.json` 中包含：

- 每段帧数；
- 实测周期；
- 恢复到的有效报文数量；
- 嵌入恢复数量；
- 校验失败数量；
- 关键时刻；
- 阶段耗时；
- 阶段顺序有效性；
- 分段元数据；
- 定位流来源。

## 11. 边界说明

以下内容不能仅凭 GNSS 日志确认，报告中不得写成确定结论：

1. 每次 GNSS 状态丢失是否对应物理断电；
2. 两台设备每次上电是否完全同步；
3. 物理断电或上电的精确时刻；
4. `APPROXIMATE` 状态是否在所有固件配置下必然出现。

如需确认上述内容，应同步记录外部开关事件、事件报文、视频或其他独立时间源。
