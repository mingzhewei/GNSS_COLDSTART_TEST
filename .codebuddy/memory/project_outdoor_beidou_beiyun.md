2026-10-26 用户确认的新执行口径与交付状态：

1. **场景边界**：文件名/用户说明中“空旷、树荫”均属**室外冷启动**；“室内冷启动”仅指文件名明确标注室内的数据。室外多产品配对逻辑必须放在 HMI 的 outdoor 分支，不能放进 indoor 分支。
2. **北斗×北云室外配对**：北云 cold 段是主切割和编号基准。北斗候选段自身依据为“长动态间断 + 无基站 + NONE/单点类 + 段内恢复差分/固定 + 卫星数骤降”；`SOL_COMPUTED` 不作为排除条件，因为 UM980 可保持 FINE 时标并很快输出 SINGLE。匹配窗口普通 ±30s、扩展 ±90s；北云时间重置段用段内首个有效 GPS 时间或后续段有效时间做工程重建。匹配后仍使用北斗自身 `BESTNAVA` 首末帧为分析边界。
3. **HMI 输出**：室外 + 自动切片 + 北斗 1 个 + 北云 1 个时，依次生成并自动打开三份报告：`beidou/report.html`、`beiyun/report.html`、根目录 `comparison.html`。北斗报告含 `paired_matching_audit`，联合报告由 `beidou_beiyun_comparison.py` 生成。
4. **北云×华测保护**：华测与北云配对继续走原有逐产品分析和 `comparison_report.py`，不得引入北云窗口套华测、不得修改华测判据。室内多产品也保持原 `indoor_coldstart.py` 序号配对路径。
5. **工程阈值边界**：±30s/±90s 匹配窗口、卫星数下降≥10颗或首帧≤上一段末尾70%均为本数据集工程判据，不是厂商协议常数；报告中必须如此标注，不得宣称其为标准。
6. **验证基线**：1026 空旷和树荫北斗×北云均为 12 对、匹配均 normal、无缺失；北云-华测历史回归为 0920树荫 8/8、0921开阔 10/10、0920室内 9/9；1023 北斗室内单文件仍 9 段。`test_coldstart_recovery.py` 全过。
7. **仓库策略**：`reports/` 与 `reports_tmp_debug/` 为可再生产物，不入库；`.mypy_cache/`、`__pycache__/` 不入库。全部北云/华测/北斗原始数据入 Git。注意 4 个 1026 北云文件超过 GitHub 推荐的 50MB（52.60–75.86MB），后续继续增大时考虑 Git LFS 或外部归档。

**Why:** 1026 室外北斗日志按旧判据只识别 1 个 cold 段，原因是多数重启首帧已是 `SOL_COMPUTED + SINGLE + 无基站 + FINE`；以北云同步测试为基准可恢复 12 次配对。HMI 曾误把新逻辑放在 indoor 分支，用户指出空旷/树荫是室外数据后已迁移；后又发现只开北斗和对比报告，已补上北云报告自动打开。
**How to apply:** 后续所有北斗×北云室外配对均走 `BEIDOU_coldstart.py --reference-beiyun`；不要把该逻辑推广到华测；不要把 GNSS 推断段等同于物理断电时刻；修改后至少回归上述 1026/北云-华测/1023 基线；报告按需生成，原始数据必须保留。
